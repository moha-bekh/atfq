# ATFQ Kubernetes orchestration

This orchestration mirrors the production Docker Compose topology from `services/`:

- edge: `net-gateway` on host ports 80/443
- frontend/API: `app-nginx`, `api-gateway`
- services: `auth`, `user`, `wiki`
- backing services: `vault`, `db-auth`, `db-user`, `db-wiki`, `redis-auth`, `mailpit`, `minio`
- jobs/monitoring: `create-buckets`, `prometheus`, `grafana`, `node-exporter`, `cadvisor`, `process-exporter`

## Namespaces and node layout

The prod/dev helmfiles deploy into separate namespaces:

- `atfq-edge`: public `net-gateway`
- `atfq-apps`: `app-nginx`, `api-gateway`, `auth`, `user`, `wiki`
- `atfq-data`: `vault`, Postgres, Redis, MinIO, bucket job
- `atfq-tools`: `mailpit`
- `atfq-observability`: Prometheus, Grafana, node/process/container exporters

Node scheduling is label based:

- `master-01`: Kubernetes control-plane only
- `worker-01`: `node-pool=workload`, app/API/frontend pods and public gateway
- `worker-02`: `node-pool=shared`, backing services and observability
- both workers: `node-class=worker`, DaemonSet exporters

Prepare the cluster before applying Helm:

```sh
KUBECONFIG=infra/orchestration/kubeconfig_atfq \
task -t infra/orchestration/Taskfile.yaml prepare-layout
```

## TLS

`net-gateway` terminates HTTPS with Let's Encrypt certificates generated by a `certbot` sidecar. Certificates are stored on the gateway node at `/var/lib/atfq/letsencrypt` and renewed every 12 hours when needed. The gateway serves the HTTP-01 challenge from `/.well-known/acme-challenge/` and redirects other HTTP traffic to HTTPS.

DNS for `atfq.org` and `www.atfq.org` must point to `worker-01`, and ports 80/443 must be reachable from the internet.

## Required Vault AppRole secrets

Compose mounts `./vault/agent_ids` from the local filesystem. Kubernetes cannot use that bind mount, so each Vault agent expects a Kubernetes Secret containing `role-id` and `secret-id`.

Create or copy these secrets before deploying:

```sh
kubectl -n atfq-apps create secret generic vault-agent-api-gateway-approle --from-literal=role-id=... --from-literal=secret-id=...
kubectl -n atfq-apps create secret generic vault-agent-auth-approle --from-literal=role-id=... --from-literal=secret-id=...
kubectl -n atfq-apps create secret generic vault-agent-user-approle --from-literal=role-id=... --from-literal=secret-id=...
kubectl -n atfq-apps create secret generic vault-agent-wiki-approle --from-literal=role-id=... --from-literal=secret-id=...
kubectl -n atfq-data create secret generic vault-agent-auth-approle --from-literal=role-id=... --from-literal=secret-id=...
kubectl -n atfq-data create secret generic vault-agent-user-approle --from-literal=role-id=... --from-literal=secret-id=...
kubectl -n atfq-data create secret generic vault-agent-wiki-approle --from-literal=role-id=... --from-literal=secret-id=...
```

The Vault KV paths remain the same as Compose:

- `secret/data/api-gateway`
- `secret/data/auth`
- `secret/data/user`
- `secret/data/wiki`

`net-gateway` no longer needs a Vault AppRole secret; TLS is handled by Certbot.

## Deploy

```sh
task -t infra/orchestration/Taskfile.yaml deploy ENV=prod
```

Use `ENV=dev` to render/apply `clusters/dev/helmfile.yaml`.

Moving existing StatefulSets from `default` to these namespaces creates new PVCs. For a demo reset, remove the old default releases before applying the namespaced helmfile. To preserve data, export/restore Vault, Postgres, and MinIO first.
